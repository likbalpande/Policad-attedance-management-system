FT (frontend) setup decisions - platform/apps/frontend, package @platform/frontend

## Stack
- Vite + React + TypeScript, @vitejs/plugin-react-swc
- Capacitor (ios/android) wrapping the same build - one codebase for desktop-browser
  (admin/faculty/super-admin) and the native student mobile app
- Styling/UI: Tailwind CSS v4 + shadcn/ui (Radix primitives copied into components/ui/)
- Routing: React Router v7, actor-scoped nested route trees, lazy-loaded per actor
- Server state: TanStack Query
- API client: two axios instances - pbClient (PB, most traffic) and lagClient (LAG,
  attendance-hash submission only) - both get the access-token request interceptor
  and both share one single-flight refresh-token queue (lib/auth-refresh.ts) on 401,
  since refresh only ever happens via PB regardless of which instance triggered it
- Client/global state: Zustand (auth/session store only - everything else is server
  state via TanStack Query, no duplication)
- Forms: React Hook Form + Zod resolver (mirrors PB's Zod convention)
- Real-time: @microsoft/fetch-event-source for the SSE attendance-status stream
  (native EventSource can't send an Authorization header, this can)
- Status polling (get_attendance_status): custom hook implementing the fixed
  5/15/30/60/75/90/105/120s schedule - not TanStack Query's fixed refetchInterval
- QR display (FTA/FTF, session hashes): qrcode.react
- QR scanning (FTS): hybrid - native scanner (@capacitor-mlkit/barcode-scanning) on
  device, web fallback (html5-qrcode or zxing) when running in a plain browser
- Token storage: Capacitor Preferences plugin (has a web impl backed by localStorage,
  so one code path works for both browser and native)
- Testing (default, not yet mandatory - matches PB's stance): Vitest + React Testing
  Library
- Workspace deps consumed as-is: @platform/types, @platform/permissions, @platform/uai
  (all build to CJS+dts via tsup; Vite/esbuild consumes that fine)
- Toasts: sonner, wrapped by lib/toast.ts - feature code imports the wrapper, never sonner
- Icons: lucide-react, wrapped by components/icons.tsx - re-exports only the icons
  actually used, under semantic names (e.g. IconEdit, not the raw lucide name)
- Dates: date-fns, wrapped by lib/date.ts
- Animation: Framer Motion (motion/react), used sparingly for purposeful micro-
  interactions only (status pill transitions, QR-refresh tick, page/panel enter)
  - not decorative, respects prefers-reduced-motion

## Convention: wrap ad-hoc-call libraries
Any library invoked directly from many unrelated call sites (toasts, icons, date
formatting, clipboard, ...) gets a thin wrapper in lib/ or components/ - feature code
never imports the vendor package directly. Centralizes defaults/styling in one place
and makes swapping the library later a one-file change. Does not apply to libraries
already centralized by construction (axios instances, TanStack Query, RHF).

Mirrors PB's actor-tier convention more precisely than a flat 1:1 actor mapping would:
PB only groups a module under an actor-tier folder when every route in it is scoped to
a single actor (super-admin's org/admin/permission-config modules); a module whose
routes span multiple actor tiers (batches, courses, ...) stays ungrouped with
per-route requireRole/checkPermission granularity instead. `app/staff/` is FT's
equivalent of that - admin and faculty share it because PB's own batches/courses/
attendance endpoints are shared, not actor-split. Route guarding: RequireRole wraps
each top-level tree (`/super-admin/*` -> super_admin, `/staff/*` -> admin|faculty,
`/student/*` -> student); wrong-role access redirects to /unauthorized, not to login,
since the user is authenticated - just the wrong tier. `shared/`, `components/`,
`hooks/`, `lib/` hold everything not scoped to one actor.

`api/` is organized by **backend resource, not by FT actor** - a delegable resource
like `batches` is used by both FTA and FTF (same PB endpoint, gated by different
permissions), matching how PB itself only nests non-delegable modules under
`super-admin/`. Actor-grouping (`super-admin/`) only applies when *every* route for
that resource is single-actor-scoped - never split a shared/delegable resource across
actor folders (would mean arbitrarily picking an owner, or duplicating the same axios
call). Within a resource, one file per endpoint/action once there's more than one -
mirrors PB's own controller/service granularity (`auth.staff-login.controller.ts` vs
`auth.refresh.controller.ts`, not one `auth.controller.ts`) rather than letting a
single `<resource>.api.ts` grow to hold every action as PB gains endpoints. A resource
with a genuinely single endpoint can stay a flat `<resource>.api.ts`/`.queries.ts`
pair; split into a folder as soon as a second action shows up. Pages/components import
only from `.queries.ts`, never call `.api.ts` functions directly - keeps loading/error/
cache state consistent through TanStack Query. Almost every `<resource>.api.ts` calls
`pbClient`; only the attendance-marking submit call (FTS scanning flow) calls
`lagClient` - keep that one isolated in its own `api/attendance-marking.api.ts` rather
than mixed into a PB-backed file.

**Never hand-type a request/response shape PB already defines.** Every
`<action>.api.ts`'s input and response type comes from `@platform/types`
(same DTO PB validates with, same entity type PB's service returns) - a
local `<resource>.types.ts` holds only TanStack Query key constants, nothing
that mirrors a PB shape. See the architecture skill's "Shared FE<->BE
contracts" section for the full rule, including why RHF form-validation
schemas (`<feature>.schemas.ts`) are the one thing that *stays* FE-local.

## Config notes
- tsconfig.json extends @platform/tsconfig/base.json, overrides module/moduleResolution
  (bundler) + jsx (react-jsx) + lib (add DOM) - keeps the @platform/* path mapping for
  go-to-definition without inheriting the CJS-oriented backend defaults
- eslint.config.js extends @platform/eslint-config/base.js + react-hooks +
  react-refresh plugins
- Env: Vite's import.meta.env, VITE_-prefixed vars, one .env (not per-environment
  files) - same "single file, identifier inside" convention as the backend apps.
  Two base-URL vars: VITE_PB_API_BASE_URL, VITE_LAG_API_BASE_URL
- RBAC on the client is UI-only (hide/disable actions user can't perform) via
  @platform/permissions vocab - never trust the client, PB still enforces every check

## Design / theme
Light mode only, minimal - explicitly not the generic AI-SaaS indigo/violet gradient
look. Direction: monochrome-first UI (near-black ink on off-white), color used only
for semantic meaning (attendance status), one restrained warm accent for interactivity.

Tokens (CSS custom properties, standard shadcn/ui token names - `background`,
`foreground`, `primary`, `muted`, `border`, etc. - defined once in styles/globals.css
under Tailwind v4's `@theme`, consumed only via Tailwind semantic classes, never a raw
hex in component code):
- background: #FCFCFB (soft off-white, not stark white, not cream)
- foreground: #17181A (near-black ink - primary text, primary button fill)
- muted-foreground: #6B6D71 (secondary text)
- border: #E7E7E5 (hairline)
- card: #FFFFFF
- accent (links, focus ring, active nav/tab, selected row): #B4650D (warm amber -
  deliberately not blue/violet; used sparingly, never as a fill color)
- status/success (present): #1F7A4D
- status/destructive (absent): #B3261E
- status/warning (pending): #B58900

Typography:
- UI + headings: Inter Tight (variable, 400-700) - one sans family, weight carries
  hierarchy, no separate decorative display face (this is a dense operational app,
  not a marketing page)
- Numeric/live data (QR countdown, session hashes/ids, timestamps, attendance counts,
  status pills): IBM Plex Mono, uppercase + letter-spaced for pills - the signature
  touch, a "departures-board" quality that's earned by the product (live QR sessions,
  ticking timers), not decorative

Shape/elevation: 8px radius (cards/inputs), 6px (buttons/badges), full-pill only for
status badges. No drop shadows beyond a 1px hairline elevation on cards/dropdowns -
borders do the separation work, not shadows.

Theming architecture: built the standard production way even though only one theme
ships now - all colors as CSS custom properties on `:root`, components reference
semantic tokens only. Adding a dark theme later means defining `.dark` overrides, not
a rewrite. No theme toggle UI until dark mode is actually requested.

Responsive: mobile-first Tailwind breakpoints; Capacitor safe-area insets
(env(safe-area-inset-*)) respected in the root layout for the native student app.
